# Backend continuation contract (PR162; not live)

Web and Android use the same HTTPS API, Google ID-token audience, server-issued
session cookie and CSRF token. Mutating routes require the configured Origin,
CSRF cookie/header and active account. Owner privilege is immutable Google sub,
never an email/role supplied by the client. Do not modify Android v0.4.11.

## Owner per-CTV mode

`PATCH /api/v2/admin/ctv-mode`

```json
{"accountId":"<CTV account UUID>","enabled":false,"expectedRevision":1,"confirmed":true}
```

Success: `{ok:true,accountId,enabled,revision}`. Non-owner 403; invalid/stale
revision or inactive/non-CTV account 409. Re-read account revision on conflict.
The account revision is shared with existing admin access edits. OFF suppresses
commission grants for all future quotes and prevents CTV discount edits. Buyer
pricing reverts to the separately approved standard pricing policy; it does NOT
rewrite previous quotes/invoices. A quote made before a mode/price change must
be re-quoted at confirmation. Historical commissions remain viewable and intact.
ON restores eligible grants. Grant edits and confirmation serialize against mode
updates. No second invoice is created. This route does not enable real checkout.

## Existing routes retained

- Admin PUT `/admin/commission-grants`; CTV PATCH `/ctv/customer-discount`.
- Account GET `/invoices` and `/invoices?id=<binding UUID>` require explicit owner-verified canonical binding.
- `/test-invoices`, `/ctv/test-report`, `/admin/test-report`: synthetic records only, not production financial reports.
- `/confirm`: remains disabled (503). Canonical signed commit and PDF/payment adapters remain pending.
